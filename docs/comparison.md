# 直连 API Key vs 本插件（经 ZCode CLI）

> 面向已经在用 DSH 桌面端、并且**已经订阅了 GLM Coding Plan** 的用户。
> 没订阅的话，请先看最后一节「为什么你没有订阅就别装」。

## 一、账单从哪出：这是最核心的区别

同一个套餐 Key，两条路，两种扣法。

### 直连 API

```
DSH agent ──HTTP──> open.bigmodel.cn/api/anthropic
                     └── 计费：账户余额，按 token 量付费
```

你付了年费的 Coding Plan 套餐，**和这条链路无关**。每次调用都从账户余额扣钱，扣到停为止。

### 经 ZCode CLI（本插件）

```
DSH agent ──spawn──> ZCode.exe（Electron 跑 zcode.cjs）
                      └── 计费：Coding Plan 套餐积分
                          ZCode 渠道标注 1.5 倍（150%）
```

官方文档把 ZCode 渠道标注为 **1.5 倍用量**。换句话说：走 ZCode 渠道，同样的活消耗 1.5 倍的套餐额度——**但那是套餐额度，不是账户余额**。

### 换个角度理解倍率

「1.5 倍」听起来是亏的。但要看分母：

| | 直连 API | ZCode 渠道 |
| --- | --- | --- |
| 额度来源 | 账户余额（充值） | 套餐积分（年费/月费） |
| 用完了 | 充值才能继续 | 等下一周期，或升级套餐 |
| 空手套白狼 | — | 否，1.5 倍消耗已经计入 |

如果你的账户余额**充值很少**（甚至没充值），而 Coding Plan 是月付/年付的——那 ZCode 渠道消耗的是你已经付过的钱，直连反而会让你额外掏钱。

**这就是本插件存在的唯一理由**：把闲置的套餐额度用起来，同时接受 1.5 倍的消耗作为代价。

## 三、多轮怎么不一样

### 直连：自己管

你要自己维护消息数组、自己决定何时裁剪上下文、自己处理重试。自己写 sessionId，自己存。

### ZCode：原生

CLI 自带 `--resume <sessionId>`。插件把上一次的 `sessionId` 传给下一次调用，ZCode 内部自己恢复完整状态：

```
第 1 轮  zcode_call({ prompt: "在 src/ 下新增 Express 服务", cwd: "D:/work/myproj" })
        → sessionId: sess_124bfb13-fc98-42c4-8056-f0b3aa584bed

第 2 轮  zcode_call({ prompt: "把测试补齐，跑到全绿",
                      cwd: "D:/work/myproj",
                      resume: "sess_124bfb13-fc98-42c4-8056-f0b3aa584bed" })
```

插件把 `sessionId` 放在返回值里，agent 记得住就能续。

## 四、上下文缓存

ZCode 支持 prompt caching。实测数据（`~/.zcode/cli/db/db.sqlite`）：

| 场景 | inputTokens | cacheReadTokens | 缓存命中率 |
| --- | --- | --- | --- |
| 全新会话首轮 | 68,334 | 3,520 | 5% |
| 系统提示已热 | 67,512 | 13,504 | 20% |
| 同 session 续接 | 68,211 | 68,160 | **99.9%** |

也就是说：**多轮续接时，几乎整段上下文都命中缓存**。这是直连 API 完全拿不到的（除非你自己实现缓存，而缓存命中需要服务端支持）。

对你的意义：多轮改造任务，第三轮之后的实际增量成本非常低。

## 五、调用成本

每次调用的固定开销来自官方客户端的系统提示：

- **单轮 inputTokens ≈ 67K–68K**（系统提示 ~49K + 工具定义 + 你的 prompt）
- 实测一次「回复两个字：就绪」的空跑：input 67,512 / output 4 tokens，耗时约 19 秒

**所以**：短问答用本插件非常不划算；多文件重构、批量修改、跑测试这类长任务才划算——因为任务本身的成本远大于那 67K 固定开销。

⚠️ 按请求次数计费：ZCode 一轮里如果有多次工具调用，可能产生多条 model 记录，逐条计费。

## 六、适用人群

✅ **适合**

- 已经订阅 GLM Coding Plan，想让它在 DSH 里干活；
- 经常要做多文件级别的编码任务（重构、批量修改、补测试）；
- 看重**可审计**——想知道每次调用实际用了哪个 provider / model / 多少 token；
- 账户余额不多，不想让主会话额度被外包任务吃掉。

❌ **不适合**

- **没有 Coding Plan 订阅** → 装了没有效果，直连 API Key 按量扣余额也一样能用；
- 只做一次性短问答 → 67K 固定开销太重；
- 不愿在机器上多装一个 Electron 客户端；
- 需要完全可控的请求参数（ZCode 的 schema 随版本变化）。

---

## 七、为什么你没有订阅就别装

本插件**没有自带任何 API Key**，也**不能**让你免费用 GLM 模型。

它的全部作用是：把你**已经付费购买**的套餐额度，从闲置状态接到 DSH 会话里。如果你没有订阅：

1. 装完插件，`setup-check.mjs` 会在「套餐 Key」一节报 ✗；
2. agent 调用 `zcode_call` 会因为缺凭据直接报错，不会退化成「随便找个 Key 跑一下」；
3. 你唯一的出路是自己去开通——而那本来就不需要这个插件。

**先确认你有 Coding Plan 订阅，再考虑安装。**
